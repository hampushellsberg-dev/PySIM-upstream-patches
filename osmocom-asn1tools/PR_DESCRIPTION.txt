codecs: fix two unbounded-loop hangs

Two bugs that cause the library to hang (infinite loop + memory leak)
were found in asn1tools. Both are reproducible with minimal ASN.1
inputs.

=== Bug 1 — circular type reference hangs the compiler ===

File: asn1tools/codecs/compiler.py, methods resolve_type_name
and resolve_type_descriptor.

These methods follow type-alias chains (A ::= B → B ::= INTEGER)
until a built-in type is reached. The only exit from the while True
loop is a CompileError raised by lookup_type_descriptor when the
name is not found in any module's type dictionary.

Neither method carries cycle detection. When type references form a
ring and the types carry explicit tags (which routes them through
pre_process_tags_type), the loop spins forever:

    CircularBreak DEFINITIONS EXPLICIT TAGS ::= BEGIN
        TypeA ::= [0] TypeB
        TypeB ::= [1] TypeA
    END

resolve_type_name('TypeB') → finds TypeA → finds TypeB →
finds TypeA → …

Reproduction:

    import asn1tools

    asn1_text = """
    CircularBreak DEFINITIONS EXPLICIT TAGS ::= BEGIN
        TypeA ::= [0] TypeB
        TypeB ::= [1] TypeA
    END
    """

    # Hangs — must be killed with a timeout
    spec = asn1tools.compile_string(asn1_text, codec="der")

Fix: add a seen set to both methods. When a type name repeats it means
the alias chain is circular; raise CompileError to break the loop.

=== Bug 2 — missing check_decode_error in DER ArrayType.decode_content ===

File: asn1tools/codecs/der.py, method ArrayType.decode_content.

The DER codec's ArrayType.decode_content (used for SEQUENCE OF and
SET OF) has a while loop that calls
self.element_type.decode(data, offset) but never calls
check_decode_error on the result. When the inner element returns
TAG_MISMATCH (offset unchanged) the loop:

  1. Appends the TAG_MISMATCH sentinel to the decoded list — memory
     grows unbounded.
  2. Spins forever because offset never advances past length.

The BER codec's equivalent loop calls check_decode_error, which
raises DecodeTagError and stops the loop. This call was missing from
the DER override.

Reproduction:

    import asn1tools

    asn1_text = """TestMod DEFINITIONS ::= BEGIN
        SeqOfInt ::= SEQUENCE OF INTEGER
    END
    """

    spec = asn1tools.compile_string(asn1_text, codec="der")

    # Malformed: BOOLEAN tag (0x01) where INTEGER tag (0x02) expected
    bad = bytes.fromhex("30090101FF020102020103")

    # Hangs — inner element returns (TAG_MISMATCH, same_offset),
    # the loop appends it and never advances.
    spec.decode("SeqOfInt", bad)

Fix: import check_decode_error from ber and call it after each
self.element_type.decode() in the DER ArrayType.decode_content
loop, matching the BER pattern.

=== Patches ===

compiler.py: +12 lines — seen set in resolve_type_name and
              resolve_type_descriptor
der.py:      +2 lines  — import and call check_decode_error in
              ArrayType.decode_content

=== Verification ===

After applying both patches:

  Circular tagged types (10 compiles)           No hang — 5 types compiled in ~0.3 s

  Normal alias chain A→B→C→INTEGER (5 compiles) All correct

  Malformed SEQUENCE OF — TAG_MISMATCH
    (50 decodes)                                DecodeTagError raised every time, no hang

  SEQUENCE OF roundtrip sizes 1–1000
    (10 cycles)                                 All correct

  Various malformed data injections (5 runs)    All handled, no hangs

  100 rapid malformed decodes                   100/100 raised cleanly, 0 hangs

  Combined circular types + SEQUENCE OF
    (5 compiles)                                No hang, roundtrips OK
